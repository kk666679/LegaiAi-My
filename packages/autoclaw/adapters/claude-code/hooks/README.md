# AutoClaw hooks for Claude Code

Deterministic, zero-LLM-cost [Claude Code hooks](https://docs.anthropic.com/en/docs/claude-code/hooks):

- `stop-gate.cjs` — **Stop** hook enforcing cross-agent protocol **rule 7**:
  never broadcast `task_complete` without a handoff-note sidecar. Pattern
  ported from xD4O/praxis (MIT).
- `session-startup.cjs` — **SessionStart** hook that prints a first-turn
  "picking up where we left off" digest (open claims, claimable tasks, inbox
  items needing action, recent decisions, latest handoffs, suggested next
  prompts) so a fresh session starts from recorded truth instead of
  confabulating it. Motivated by the xD4O/exocortex review (MIT).

> These files are hand-maintained. They are **not** generated by `scripts/build-adapters.ts`
> (the generator only owns `adapters/<tool>/<skill>/…` skill transforms), so
> `npm run adapters:check` ignores them.

---

# Stop-gate hook (`stop-gate.cjs`)

## What it blocks

When the Claude Code session tries to stop, the hook exits `2` (blocking the
stop, with a one-line reason on stderr) if — for **this session's**
`session_id` only:

1. A `task_complete` message in `.autoclaw/orchestrator/comms/inboxes/shared/`
   (or `shared/processed/`) has no handoff sidecar on disk — neither the
   `payload.handoff_note` path nor the conventional
   `comms/handoffs/<task-id>-<first-8-session-chars>.json`.
2. A claim in `comms/claims/` is owned by this session but the owning agent has
   **no heartbeat file** in `comms/heartbeats/` (the claim looks abandoned and
   will be reaped).

Everything else exits `0` (stop allowed).

## Guarantees

- **One nudge, never a loop.** Claude Code sets `stop_hook_active: true` when a
  session is already continuing because of a Stop hook. The gate always exits
  `0` in that case, so it can block a given stop at most once.
- **Absolute fail-open.** Malformed stdin, a broken comms tree, unreadable
  JSON, or a missing build all exit `0`. The gate can only ever add one useful
  nudge; it can never trap a session.
- **Bounded.** At most the newest 200 shared messages and 200 claim files are
  scanned.
- **Session-id mapping.** Claude Code's hook `session_id` (transcript session)
  is not guaranteed to equal the agent-protocol session UUID stamped on
  messages/claims/heartbeats. When the raw id matches **nothing** in the comms
  tree, the gate reads the agent's own heartbeat
  (`comms/heartbeats/<agent>.json`, agent id from `AUTOCLAW_AGENT_ID`, default
  `claude-code`) and scans as its `session_id` instead — but **only** when
  that heartbeat is fresh (~2 h). A stale or missing heartbeat keeps the raw
  id, i.e. the old fail-open behavior. Set `AUTOCLAW_AGENT_ID` when the
  session is registered under another agent id.
- **Zero dependencies.** `node:fs` + `node:path` only. It prefers the compiled,
  unit-tested gate at `out/orchestrator/stopGate.js` and falls back to an
  inline port when no build exists.

## Register it

Add to `.claude/settings.json` (project) or `~/.claude/settings.json` (user):

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR/adapters/claude-code/hooks/stop-gate.cjs\""
          }
        ]
      }
    ]
  }
}
```

For a workspace that consumes AutoClaw as an extension (no `adapters/` dir),
copy `stop-gate.cjs` anywhere stable (e.g. `.claude/hooks/`) and point the
command at that path — the script is self-contained.

## Disable it

Either of:

- Remove the `Stop` hook entry from settings.json, or
- Set the environment variable `AUTOCLAW_STOP_GATE=0` (kill switch — the hook
  exits `0` immediately).

## Testing

The decision logic lives in `src/orchestrator/stopGate.ts` (pure, synchronous,
vscode-free) and is covered by `src/test/stopGate.test.ts`:

```
npx mocha --ui tdd --timeout 20000 out/test/stopGate.test.js
```

# Session-startup hook (`session-startup.cjs`)

On session start/resume, Claude Code runs the hook and injects its **stdout**
into the session's context. The hook prints the ≤25-line `text_for_user` block
from `buildSessionStartupDigest` (src/orchestrator/sessionStartup.ts):

- **Your open claims** — this agent's live claims in `comms/claims/`.
- **Claimable now** — top unclaimed, dependency-satisfied tasks from
  `.autoclaw/orchestrator/board.json`.
- **Inbox needing action** — pending messages in this agent's inbox
  (`review_request`s first; replied/archived items excluded).
- **Recent decisions** — newest closed consensus records
  (`comms/consensus/{resolved,closed}/`).
- **Latest handoffs** — newest handoff notes (ones addressed to this agent
  sort first), with human-aged timestamps ("2h ago").
- **Suggested next** — 2–3 concrete prompts ("Continue task …",
  "Answer pending review_request …", "Claim …").

## Guarantees

- **Absolute fail-open.** Any error prints NOTHING and exits `0`. A
  SessionStart hook must never block or pollute a session.
- **Silent outside fleets.** No `.autoclaw/orchestrator/` directory → no
  output, so foreign projects get zero noise.
- **Bounded + agent-scoped.** At most 200 files per directory are scanned;
  only THIS agent's claims and inbox are read (identity from
  `AUTOCLAW_AGENT_ID`, default `claude-code`).
- **Zero dependencies.** `node:fs` + `node:path` only. Prefers the compiled,
  unit-tested digest at `out/orchestrator/sessionStartup.js`; falls back to a
  compact inline port when no build exists.

## Register it

Add to `.claude/settings.json` (project) or `~/.claude/settings.json` (user):

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$CLAUDE_PROJECT_DIR/adapters/claude-code/hooks/session-startup.cjs\""
          }
        ]
      }
    ]
  }
}
```

Use matcher `"startup|resume|clear"` to also re-inject after `/clear`. For a
workspace that consumes AutoClaw as an extension (no `adapters/` dir), copy
`session-startup.cjs` anywhere stable (e.g. `.claude/hooks/`) and point the
command at that path — the script is self-contained.

Set `AUTOCLAW_AGENT_ID` in the environment when the session is not
`claude-code` (e.g. a second window registered under another agent id).

## Disable it

Either of:

- Remove the `SessionStart` hook entry from settings.json, or
- Set the environment variable `AUTOCLAW_SESSION_STARTUP=0` (kill switch — the
  hook prints nothing and exits `0` immediately).

## Testing

vscode-free) and is covered by `src/test/sessionStartup.test.ts`:

```
npx mocha --ui tdd --timeout 20000 out/test/sessionStartup.test.js
```
